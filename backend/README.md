# Backend прогноза ветроэнергии

Go 1.25.6 и Gin. Публичный API описан в [OpenAPI](api/openapi.yaml). Сейчас по умолчанию работает **синтетический mock**; ответ помечается `data_mode=fixture`, модель — `fixture-not-trained`. Настоящего прогноза CatBoost, GFS, LangGraph и данных SCADA здесь пока нет.

## Запуск

Установите Docker Desktop либо Docker Engine с Compose. Из корня репозитория:

```sh
cd backend
docker compose up --build
```

После запуска откройте <http://127.0.0.1:8080/docs>. API доступен по адресу <http://127.0.0.1:8080>. Первый запуск требует интернет для загрузки образа и Go-зависимостей. На Windows, macOS и Linux команды одинаковы; Docker собирает образ под архитектуру текущего компьютера. Для остановки нажмите `Ctrl+C`, для следующего запуска достаточно `docker compose up`. Compose привязывает порт только к `127.0.0.1`, то есть API доступен на этом компьютере. Для общего доступа нескольких ноутбуков понадобится серверный адрес, HTTPS и авторизация: их в текущем локальном Compose нет.

Если установлен Go 1.25.6, можно запустить без Docker: из папки `backend` выполнить `go run ./cmd/api`. Настройки перечислены в [.env.example](.env.example); Go читает переменные окружения, а не загружает этот файл автоматически.

## Что реализовано

| Возможность | Текущее состояние |
|---|---|
| `GET /healthz`, `/readyz`, `/api/meta`, `/api/turbines`, `/api/models` | Работают; каталог mock содержит только синтетическую модель и две настроенные, но не подтверждённые турбины. |
| `POST /api/forecast-runs` → `GET /api/jobs/{id}` → `GET /api/forecast-runs/{id}/result` | Асинхронный прогноз mock на 24/48 часов. Результат появляется после завершения задания. |
| История, детали, погода, объяснение, CSV | Реализованы; погода и оценки в mock синтетические, SHAP недоступен. |
| События и SSE (`/api/jobs/{id}/events`, `/stream`) | Журнал событий, возобновление по курсору, завершение потока. |
| Idempotency-Key, отмена, replay | Повтор с тем же ключом возвращает задание; другой запрос с тем же ключом даёт 409. Есть отмена и пакетный replay с частичным CSV по явному запросу. |
| Оценки качества и аудит данных | Только обозначенные fixture-ответы; это не измеренная точность модели. |
| `AGENT_MODE=http` | Подготовлен HTTP-адаптер к Python-протоколу. С реальным ML-сервисом пока не подключён. |

Все пути, параметры, коды ошибок и схемы ответов приведены в [OpenAPI](api/openapi.yaml). Схема встроена в бинарник и используется для проверки входящих данных. TypeScript [типы](contracts/typescript/api-types.ts) и [клиент](contracts/typescript/client.ts) предназначены для фронтенда. Инструкция фронтендеру — [здесь](docs/FRONTEND_HANDOFF.md).

Пример запроса из PowerShell после запуска:

```powershell
$headers = @{ 'Idempotency-Key' = [guid]::NewGuid().ToString() }
$body = @{ forecast_origin = '2026-01-31T18:00:00Z'; model_version = 'fixture-not-trained'; data_mode = 'fixture' } | ConvertTo-Json
$job = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/forecast-runs' -Headers $headers -ContentType 'application/json' -Body $body
$job
Invoke-RestMethod "http://127.0.0.1:8080/api/jobs/$($job.job_id)"
```

`POST` возвращает `202` и `job_id`, а не готовый график. После статуса `completed` результат доступен по `/api/forecast-runs/{job_id}/result`. Для фронтенда удобнее использовать TypeScript-клиент с SSE.

## Архитектура и интеграция ML

`internal/domain` содержит типы и правила без Gin/HTTP. `internal/application` содержит сценарии и интерфейсы портов. `internal/adapters/agentmock` и `agenthttp` реализуют порты. Контроллеры в `internal/transport/http/handlers` обращаются только к сценариям. `internal/app.New` — единственная точка сборки зависимостей и жизненного цикла. Подробная схема — в [ARCHITECTURE.md](docs/ARCHITECTURE.md).

При появлении ML нужно сопоставить его реальные маршруты и модели данных с [согласованным внутренним протоколом](docs/PYTHON_INTEGRATION.md), затем настроить `AGENT_MODE=http`, `ALLOW_FIXTURES=false`, `PYTHON_BASE_URL` и внутренний токен. [compose.http.yaml](compose.http.yaml) — настройка для отдельно запущенного Python-сервиса; сам Python-сервис в Compose пока отсутствует. Если ML API отличается, меняется адаптер или фиксируется изменение в [журнале контракта](docs/CONTRACT_CHANGELOG.md); публичный API без такого изменения не переименовывается. Для одной команды на нескольких ноутбуках после появления ML и фронтенда их сервисы следует добавить в общий Compose с именами сервисов вместо адреса конкретного ноутбука.

Mock хранит задания и ключи идемпотентности **только в памяти**. Перезапуск их удаляет; при заполнении очереди или лимита хранилища новые задания получают 503. Для реальной эксплуатации Python должен обеспечить долговечное принятие заданий, результаты и восстановление после перезапуска. Реальная погода, обучение модели, точность, SHAP и историческая достоверность пока не проверены. Мощность турбин и единицы для перевода в MW/MWh не подтверждены, поэтому API их не выдумывает.

## Поддержка контракта

Файл [tools/generate_contract.py](tools/generate_contract.py) создаёт OpenAPI, Go DTO/сопоставления и TypeScript-типы из одного определения. Он нужен при изменении публичного контракта; это не тестовый файл и не часть запуска API. Проверить совпадение артефактов можно командой `python tools/generate_contract.py --check`. CI/CD здесь нет. По запросу удалены автоматические тесты, статические снимки fixture, smoke-утилита и Python-помощник без ML; текущая проверка после очистки описана в [аудите](docs/AUDIT.md).
