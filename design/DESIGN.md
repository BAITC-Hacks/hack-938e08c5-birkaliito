# AURA — спецификация интерфейса

## Основной сценарий

1. Пользователь открывает «Прогноз».
2. Выбирает горизонт: 24 или 48 часов.
3. Нажимает «Рассчитать».
4. Backend получает один `mode=live` запрос для турбин 1 и 2.
5. Интерфейс показывает две отдельные карточки с графиками.

Дата выпуска автоматически округляется до текущего часа UTC. Выбора периода и
пакетного replay в интерфейсе нет.

## Страницы

- Главная — короткий вход в продукт и последний готовый выпуск.
- Прогноз — выбор 24/48 часов и отдельный график каждой турбины.
- Аналитика — история уже созданных выпусков и почасовая таблица.
- Исходные данные — доступный аудит входных данных.

Страницы replay, оценки модели и agent/source удалены как лишние для сценария ТЗ.

## Контракт backend

Frontend не меняет backend DTO. Запрос прогноза содержит:

```json
{
  "forecast_origin": "RFC3339, целый час UTC",
  "horizon_hours": 24,
  "turbine_ids": [1, 2],
  "mode": "live",
  "model_version": "версия из /api/models",
  "data_mode": "fixture"
}
```

Допустимы только `horizon_hours=24` и `48`. Результат отображает
`power_mean` и диапазон `q10–q90` отдельно для каждой турбины.

## Принципы

- Один основной CTA и минимум поясняющего текста.
- Нормализованная мощность не называется кВт или МВт.
- Fixture всегда обозначается как синтетический режим.
- Ошибка, очередь и расчёт показываются коротким статусом.
- На мобильном карточки турбин располагаются одна под другой.
