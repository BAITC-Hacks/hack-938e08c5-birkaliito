# Аудит backend — 23 сентября 2026

## Состав после очистки

Рабочий сервис находится в `cmd/api` и `internal`. Канонический публичный контракт — `api/openapi.yaml`; из него получены Go DTO и `contracts/typescript/api-types.ts`. `tools/generate_contract.py` оставлен как генератор при будущих изменениях API. `agentmock` создаёт fixture-результаты во время работы; он не читает удалённые статические JSON-снимки. `agenthttp` оставлен для подключения будущего Python ML. `compose.yaml` запускает Go API; `compose.http.yaml` только переключает его на отдельно работающий Python-сервис.

Удалены тестовые Go-файлы, папка `tests`, 53 статических fixture-снимка, генератор этих снимков, smoke CLI, тест TypeScript, Python-помощник без ML, тестовый контейнерный скрипт и дублирующие команды Make/PowerShell. Удалены устаревшие demo/verification инструкции и копия исходного master prompt внутри backend. CI/CD в репозитории не обнаружен и не добавлялся. Исходный `wind_backend_handoff/baseline_contracts` за пределами репозитория оставлен как исторический первоисточник контракта; сервис его не использует, текущий фронтенд должен брать типы из `backend/contracts/typescript`.

## Проверка архитектуры

| Граница | Результат просмотра |
|---|---|
| `domain` | Не импортирует Gin, транспорт или адаптеры; содержит правила времени, покрытия по турбинам и квантилей. |
| `application` | Сценарии forecast, job, replay, catalog и evaluation работают с доменом и портами. Replay переиспользует проверку forecast через сервис. |
| `transport/http/handlers` | Держит интерфейсы сценариев, преобразует DTO, отвечает за HTTP/CSV/SSE; прямых импортов `agentmock`, `agenthttp` и хранилища не найдено. |
| `adapters` | Mock владеет очередью и состоянием в памяти; HTTP-адаптер переводит отдельные внутренние DTO и проверяет ответы Python. |
| `app.New` | Единственная точка сборки конкретных зависимостей; конфигурация читается при создании приложения. |

Публичные маршруты не изменены. OpenAPI, Go DTO и TypeScript-типы остаются единым комплектом. Контроллеры вызывают сценарии; исключение по смыслу — технические преобразования DTO и выдача HTTP-потока в самом транспортном слое. Docker привязывает API к localhost. Для фронтенда разрешены оба обычных локальных адреса Vite: `localhost:5173` и `127.0.0.1:5173`.

## Что действительно работает и что ещё не готово

В режиме `mock` работают создание прогноза, состояние задания, результат 24/48 часов, SSE и опрос событий, идемпотентность, отмена, replay, история, CSV, fixture-погода и fixture-метрики. Данные помечены `fixture`. SHAP недоступен. Хранилище и ключи идемпотентности исчезают после перезапуска; лимиты очереди и памяти приводят к 503.

Адаптер `AGENT_MODE=http` компилируется, но реальный Python-сервис, обученная модель, GFS, SCADA и фронтенд не предоставлены. Поэтому реальный прогноз, точность, историческая доступность входных данных, устойчивость Python-заданий после перезапуска и запуск всей системы одним Compose **не проверены**. До подключения ML нужно согласовать внутренние маршруты и DTO по `PYTHON_INTEGRATION.md`, проверить реальный ответ на всём цикле задания и добавить Python/фронтенд сервисы в Compose. Если изменится публичная форма ответа, сначала обновить OpenAPI и клиентские типы. Для доступа сотрудников с разных ноутбуков также потребуются серверное размещение, HTTPS и авторизация; сейчас Compose рассчитан на локальную разработку.

## Выполненные проверки

Перед удалением тестового набора прошли `go test ./...`, `python tools/generate_contract.py --check` и `docker compose config --quiet`. После очистки прошли `go build ./...`, `go vet ./...`, повторная сверка сгенерированного контракта, `npm run typecheck` и проверка конфигурации обоих вариантов Compose.

Команда `docker compose up --build -d` собрала и запустила итоговый образ. Через работающий контейнер вручную проверены `/healthz`, `/api/meta`, создание прогноза, повтор с тем же ключом и тем же ID, конфликт с другим телом (409), завершение задания, 96 точек результата, 5 событий и CSV из 97 строк. Replay с двумя origin и горизонтом 24 часа завершился с двумя дочерними заданиями и CSV из 97 строк; SSE отдал три события и `stream_end`. После проверки контейнер остановлен.

Автоматических тестов теперь нет: дальнейшие изменения не будут автоматически обнаруживать регрессии поведения. Это осознанное последствие запрошенной очистки, особенно существенное при подключении ML.
